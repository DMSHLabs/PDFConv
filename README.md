# pdfconv — окно-конвертер Markdown и LaTeX в PDF и DOCX

Личный инструмент, отдельный проект. Два способа отдать текст на конвертацию:

- **вкладка «Файлы»** — перетащите в окно `.md`, `.markdown`, `.tex`, `.latex` или `.docx`;
  результат появится рядом с исходником;
- **вкладка «Текст»** — вставьте markdown из буфера (кнопка «Вставить из буфера» или Ctrl+V),
  при желании поправьте прямо в поле и нажмите «Конвертировать текст»; результат появится в
  папке для текста (по умолчанию `Документы\PDFConv`, меняется кнопкой «Изменить папку…» и
  запоминается).

Форматы выбираются галочками в строке **Convert to: pdf / docx / md**. Для `.docx`-файлов
галочка **md** включается автоматически — это восстановленный текст с формулами LaTeX
(см. «DOCX с формулами MathType»). Ничего никуда не отправляется, всё считается локально,
а саму папку можно копировать целиком: внутри и pandoc, и Perl для latexmk, и
python-зависимости.

## Запуск

- **`PDFConv.exe`** — самостоятельный файл: Python внутри, ставить его не нужно. Запускается
  двойным кликом, окно то же самое. Рядом должны лежать `bin\pandoc\pandoc.exe` (для `.md`
  и DOCX) и на машине должны быть установлены MiKTeX и Perl (для PDF, см. «Что внутри»). Из-за
  распаковки во временную папку стартует около трёх секунд.
- `pdfconv.cmd` — тот же конвертер, но через установленный Python (стартует быстрее).
- `pyw -3 src\pdfconv.pyw отчёт.md статья.tex` — окно сразу с готовым списком файлов.
- `py -3 src\convert.py --check` — текстовый отчёт об окружении.
- `py -3 src\convert.py [--formats pdf,docx] файл.md файл.tex` — конвертация без окна.
  По умолчанию оба формата; `--formats pdf` или `--formats docx` — только нужный.
- `py -3 src\check_gui.py` — быстрая проверка окна без показа (вкладки, галочки, защита
  от пустого выбора).
- `src\build-exe.cmd` — пересобрать `PDFConv.exe` (нужен `py -3 -m pip install pyinstaller`).

Окно запоминает свой размер: растянули — при следующем запуске откроется таким же (в `pdfconv.json`).

## Как устроено окно

Сверху заголовок и вкладки, снизу кнопки, выбор форматов, прогресс и «Журнал». Между ними —
сплиттер: если журналу нужно больше места (или наоборот, вкладкам), потяните за него, положение
запомнится вместе с размером окна. Подзаголовок под названием переносится по строкам, если окно
узкое.

## DOCX с формулами MathType → Markdown

Для работы с научным текстом удобно отдавать его в `.md` с формулами LaTeX. Маршрут для
документов, где формулы набраны MathType:

1. **Один раз** сгенерировать транслятор с кириллицей: `py -3 src\make_mathtype_translator.py` —
   файл появится в `res\LaTeX Cyrillic.tdl` (охват: весь блок Ѐ–џ и Ґ/ґ; четыре редкие буквы,
   которых нет в русской Windows-кодировке, выводятся LaTeX-акцентами). Скопируйте его в
   `C:\Program Files (x86)\MathType\Translators\` (нужны права администратора). Штатный
   транслятор без этих правил падает на первой кириллической букве (Р_накр и т.п.), и
   пакетная конвертация **молча выбрасывает формулу**.
2. В Word на документе: MathType → **Convert Equations** → цель «Text using the MathType
   translator: LaTeX (Cyrillic)» — формулы становятся текстом `$…$` и `\[…\]`.
3. Перетащить полученный `.docx` в конвертер — галочка **md** включится сама, рядом появятся
   `имя.md` (формулы LaTeX) и папка `имя.media` (картинки). Если отмечен и формат **docx**,
   получится добавочная копия `имя.converted.docx` — в ней формулы MathType-текста становятся
   обычными формулами Word; **исходный docx при этом никогда не изменяется**.

Конвертер ловит потери: если в документе остался номер формулы без формулы, в журнале будет
предупреждение — такую формулу переведите по одной (в MathType: открыть, Ctrl+A, Ctrl+C,
вставить в md). В PDF-версии того же документа выделения маркером из Word переводятся в
обычный текст: пакет soul, которым pandoc рисует их, не работает с кириллицей под xelatex.

## Проверка и перенос на другую машину

```cmd
py -3 src\bootstrap.py --install   :: проверить/поставить зависимости в lib\ + подсказки
py -3 src\selfcheck.py            :: окружение + пробная конвертация + наличие файлов
```

`bootstrap.py` без `--install` только проверяет и подсказывает, что скачать (pandoc, Perl,
MiKTeX); с `--install` сам ставит python-зависимости из `requirements.txt` в `lib\` тем
интерпретатором, которым запущен. Список версий — в `requirements.txt`.

Папку можно копировать целиком: pandoc, зависимости и иконка лежат внутри. На новой машине нужны
только MiKTeX и Perl для него (см. «Что внутри»), а если хочется запускать через Python или
пересобирать exe — ещё Python 3.10+ x64 с python.org. На этой машине проект идёт под Python
3.15 (`py -3`, `pyw -3` — это он; в примерах ниже команды уже с этой версией), и зависимости
в `lib/` собраны под тот же интерпретатор. Сам `PDFConv.exe` в Python не нуждается. Полное
описание проекта, всех проверок и известных проблем — в `CONTEXT.md`.

## Что показывает «Журнал»

Журнал внизу окна — единственное место, где видно происходящее. При запуске он выводит отчёт
о проверке окружения: что найдено, а чего не хватает — с командой установки и ссылкой
(ссылка открывается по клику). Кнопка «Проверить окружение снова» повторяет проверку и дописывает
новый отчёт в журнал — удобно после установки pandoc или MiKTeX, не перезапуская окно.
Отдельной строкой идёт проверка «MiKTeX: посторонние файлы в рабочем каталоге»: здоровая
установка ничего лишнего не создаёт, а вот включённое в MiKTeX логирование в файл с
*относительным* путём создаёт каталог вроде `l` рядом с программой и мешает сборке — проверка
об этом скажет и подскажет, что поправить в MiKTeX Console.

Проверка не просто ищет файлы, а **собирает пробные документы** через pdflatex и xelatex,
поэтому ловит неполную или сломанную установку MiKTeX. Отдельной строкой идёт состояние
автоустановки пакетов: на свежем MiKTeX она должна быть включена, иначе первая сборка падает
на отсутствующем пакете. Если сборка не идёт из-за отсутствия Perl (latexmk в MiKTeX 26.5 —
Perl-скрипт), отчёт скажет об этом прямо и подскажет, что поставить.

Дальше в журнал попадают результаты по каждому файлу: путь к готовому PDF/DOCX, предупреждения,
ошибки и, в конце партии, три итоговые строки. Если `.md` ссылается на картинку, которой рядом
нет, конвертация продолжится, но в журнале будет перечислено, каких файлов не хватает, а в PDF
вместо пропавшей картинки встанет пометка «картинка не найдена: имя.jpg». Подписи к рисункам:
alt-текст картинки — это только подпись, номер «Рис. N:» LaTeX добавляет сам; не начинайте alt
с «Рис. 7.» — иначе в PDF получится «Рис. 1: Рис. 7. …». Если PDF не собрался,
в журнале видна **первая
ошибка LaTeX** и подсказка, что делать; полный журнал сборки сохраняется рядом с исходником
как `<имя>.latex.log` — и при ошибке, и при успешной сборке с предупреждениями (тогда в журнале
видны типы технических предупреждений). Текст журнала можно
выделять мышью, а по правому клику — «Копировать» и «Выделить всё»: удобно утащить весь отчёт целиком.

## Как работает вкладка «Текст»

Текст сохраняется в `.md`-файл, и дальше идёт по тому же пути, что и перетащенный файл.
Имя берётся из первого заголовка `#` (например, `# Отчёт по датчикам` → `Отчёт по датчикам.md`),
если заголовка нет — `Текст.md`; когда такое имя уже занято, добавляется отметка времени.
Формулы переносятся как есть: `$…$` в строке, `$$…$$` отдельным блоком. Выбранная папка
хранится в `pdfconv.json` рядом с программой (в git не попадает). В поле работает Ctrl+V,
правка и **правый клик → «Вставить»** — вставка в позицию курсора (кнопка «Вставить из
буфера» заменяет содержимое поля целиком, контекстный пункт — вставляет как редактор).

## Что внутри

В корне лежат только `PDFConv.exe`, `pdfconv.cmd`, эта документация и рабочие каталоги:

| Что | Где |
|-----|-----|
| код (единственная точка правды) | `src/convert.py`, `src/pdfconv.pyw` |
| проверки и сборка | `src/check_gui.py`, `src/make_icon.py`, `src/build-exe.cmd`, `src/make_mathtype_translator.py` |
| подготовка на новой машине | `src/bootstrap.py`, `src/bootstrap.cmd`, `requirements.txt` |
| pandoc 3.11 (Windows x64), нужен для `.md` и DOCX | `bin/pandoc/pandoc.exe` |
| Perl для latexmk (Strawberry portable 5.42.3.1, 75 МБ): MiKTeX 26.5+ без него PDF не собирает | `bin/perl/` (`perl\bin` + `perl\lib` целиком) |
| локальные Python-зависимости: `tkinterdnd2` (перетаскивание), `pymupdf`/`pdfminer.six`/`pypdf` (проверка PDF; все под MIT/BSD/AGPL — см. ниже) | `lib/` |
| иконка окна и exe; транслятор MathType с кириллицей (рисуются `src/make_icon.py` и `src/make_mathtype_translator.py`) | `res/PDFConv.ico`, `res/LaTeX Cyrillic.tdl` |
| локальные настройки окна (папка для текста, размер) | `pdfconv.json`, создаётся при первом изменении |

`bin/` и `lib/` не хранятся в git (см. `.gitignore`): бинарники большие и всегда
перекачиваются. Восстановить python-зависимости (любым способом):

```
py -3 -m pip install --target "D:\Projects\PDFConv\lib" -r requirements.txt
py -3 src\bootstrap.py --install        :: то же + проверка, чего не хватает
```

(путь — если папка переехала, подставьте новый). Проверка PDF работает с любым из трёх бэкендов:
`pymupdf` — основной (точный и быстрый), `pdfminer.six` (MIT) и `pypdf` (BSD) — резервные, если
pymupdf нет или им нельзя пользоваться по лицензии (AGPL). В релизном exe без pymupdf берётся
`pypdf`; ставить можно сколько угодно — конвейер выберет первый доступный.

pandoc: скачать `pandoc-*-windows-x86_64.zip` со страницы
<https://github.com/jgm/pandoc/releases/latest> и положить `pandoc.exe` в `bin/pandoc/`.
Если pandoc не найден здесь, он ищется в `C:\Tools\pandoc` и в `PATH`.

Кроме этого нужен MiKTeX (<https://miktex.org/download>) — он даёт `latexmk`, `xelatex`,
`pdflatex` и сам доустанавливает недостающие пакеты. В MiKTeX Console полезно включить
Settings → «Install missing packages on-the-fly: Yes».

Начиная с MiKTeX 26.5 `latexmk` — это Perl-скрипт, а интерпретатор Perl в состав MiKTeX не
входит. Свежий Perl лежит прямо в проекте (`bin\perl`, Strawberry portable) и выбирается
конвертером первым — ставить что-то не нужно. Запасные варианты, если `bin\perl` удалён:
свежий Perl в `PATH` или portable-сборка в `C:\Tools\strawberry-perl`. Обновить вендорный Perl
легко: скачать portable-архив со <https://strawberryperl.com/>, распаковать и заменить в нём
каталоги `perl\bin` и `perl\lib` (они же — содержимое `bin\perl`). Проверка:
`latexmk --version` должен печатать номер версии, а не «could not find the script engine».
Конвейеру нужен только сам интерпретатор, пакеты Perl не требуются.
Программа сама находит свежий Perl по всему `PATH` и в стандартном месте
`C:\Tools\strawberry-perl\perl\bin` и ставит его первым для своих сборок — даже если в
*системном* `PATH` остался старый Perl (например, ActiveState 5.8), который иначе затирал
бы свежий: пользовательский `PATH` в Windows приписывается после системного.

Внешняя обёртка `C:\Tools\pandoc\pdfbuild.py` (и `pdfbuild.cmd`) своей логики не имеет —
она подключает этот модуль и пробрасывает аргументы, поэтому привычная команда
`pdfbuild.cmd отчёт.md` продолжает работать без дублирования кода. Каталог проекта можно
переопределить переменной окружения `PDFCONV_DIR`.

## Как собирается результат

**DOCX** делает pandoc из исходника как есть: формула становится объектом Word (OMML) и
остаётся редактируемой, таблицы и заголовки сохраняются как обычные элементы Word.
После сборки проверяются текст, число формул и таблиц.

**PDF** идёт через LaTeX-конвейер, который лечит три беды, из-за которых сборка
«как есть» выглядит сломанной:

* **текстовый слой.** В pdflatex-преамбулу с кодировкой T2A добавляется `cmap`, иначе
  кириллицу в готовом PDF нельзя ни найти, ни скопировать (извлекается мусором или
  пустыми глифами). Преамбулы с `fontspec` собираются через xelatex;
* **поля.** Поднимается `\emergencystretch`, а внутри `\texttt` включаются переносы:
  длинная неразрывная математика и идентификаторы вроде `std::mersenne_twister_engine`
  иначе вылезают за правое поле и обрезаются краем листа;
* **таблицы и формулы.** Если таблица шире текстового блока, сборка повторяется: сначала
  уменьшаются отступы таблицы, затем её шрифт, в крайнем случае таблица сжимается
  `\resizebox` до ширины текста. Ступени применяются по очереди, пока переполнение
  не исчезнет. Выключные формулы LaTeX сам не переносит — широкая формула (как (1.33)
  в диссертации) измеряется и при необходимости масштабируется до ширины текста,
  о чём пишется примечание в журнале.

Маршрут `.md → PDF` сначала превращается в LaTeX через pandoc, дальше идёт тот же путь.
После сборки проверяется число страниц и живой ли текстовый слой — первым доступным бэкендом:
`pymupdf` (если установлен), иначе `pdfminer.six`, иначе `pypdf`; если нет ни одного, проверка
мягко пропускается (в журнале так и написано). Итог по партии файлов выводится тремя строками:
сколько сконвертировано без ошибок, с предупреждениями и с ошибками; подробности по каждому
файлу — в журнале.

## Настройки

Параметры сборки (шрифты, поля, размер страницы) лежат константами в начале
`convert.py`: `PANDOC_ARGS`, `STRETCH`, `TABLE_FIT`, `TABLE_FIT_SMALL`,
`BENIGN_WARNINGS`. Список форматов — `FORMATS` / `DEFAULT_FORMATS`.
