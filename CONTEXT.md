# PDFConv — полное описание проекта

Документ для агента (и человека), который оказался за этой папкой впервые: здесь всё, что нужно,
чтобы проверить проект, не изучая код. Правила работы — в `AGENTS.md`, описание для пользователя —
в `README.md`, состояние работы — в `HANDOFF.md`. Этот файл — самая подробная версия.

Проект ни с чем не связан: отдельная папка, всё локально, сеть в рантайме не нужна.

---

## 1. Что делать в первую очередь на новой машине

```cmd
py -3 src\bootstrap.py --install   :: проверка + установка python-зависимостей в lib\
py -3 src\selfcheck.py             :: полная проверка: окружение + пробная конвертация + файлы
```

Ожидаемый результат при здоровом окружении: восемь строк `OK` в разделе окружения, PDF на 1
страницу с ищущимся текстом, DOCX с двумя формулами Word, все файлы на месте и в конце
`ИТОГ: всё на месте, конвертация проверена`. Код возврата `0`. Если что-то не так — в выводе будет
строка `НЕТ …` и «что сделать», а ниже — разделы этого файла с разбором.

Готовый текст первого сообщения для нового таска (скопировать целиком):

```
Ты работаешь в проекте PDFConv — окно-конвертер Markdown/LaTeX в PDF и DOCX.
Прочитай AGENTS.md, CONTEXT.md и HANDOFF.md — там всё устройство проекта, инварианты
и известные проблемы с лечением. Затем выполни проверку:

    py -3 src\selfcheck.py

Ожидаемый результат: восемь строк OK в окружении, PDF с ищущимся текстом, DOCX с формулами,
все файлы на месте, код возврата 0. Если что-то не так — определи причину по разделу
«Известные проблемы» в CONTEXT.md и почини (для MiKTeX нужны права администратора).
Ничего в проекте не переписывай без необходимости: конвейеры уже отлажены.
```

Без Python (только exe): запустить `PDFConv.exe` и посмотреть «Журнал» — там тот же отчёт
о проверке окружения, включая пробную сборку LaTeX.

| pandoc 3.11 | вендорен в `bin\pandoc\pandoc.exe` | да для `.md` и DOCX |

Python ставить с python.org (не из Microsoft Store): нужны `tkinter` (входит в установщик),

бинарные зависимости (`pymupdf`, `cryptography` для pdfminer) ставятся под тот Python,
которым запускается проект.

## 4. Как всё устроено

### 4.1 Конвейер PDF

1. **`.md`** → `pandoc -s -t latex` с параметрами `PANDOC_ARGS` (шрифты, `geometry:a4paper`,
   `margin=2.5cm`, `fontsize=12pt`, `CJKmainfont`). Математика передаётся в LaTeX дословно.
   **`.tex`** — берётся как есть.
2. **`prepare()`** правит преамбулу:
   - `cmap` — если в файле нет `fontspec` (то есть собирать будет pdflatex). Без него кириллица
     в готовом PDF не ищется и не копируется (извлекается как `ÐÀÇÄÅË` или пустые глифы).
     Подключается **до** `fontenc`: загруженный после, `cmap` пишет «fontenc already loaded —
     some fonts may be unprocessed» и оставляет T2A-шрифты без обратного соответствия —
     ровно тот же непоисковый текст, от которого лечит;
   - `\setlength{\emergencystretch}{8em}` — чтобы длинная неразрывная математика и
     идентификаторы не уезжали за правое поле;
   - `\usepackage[htt]{hyphenat}` — если в тексте есть `\texttt`, чтобы длинные идентификаторы
     переносились.
3. **Движок**: `pdflatex` для T2A-преамбул (без `fontspec`), `xelatex` для остальных.
   Запускается `latexmk <engine> -interaction=nonstopmode main.tex` в отдельном временном каталоге.
   Для `.tex` в `TEXINPUTS`/`BIBINPUTS` добавляется каталог исходника — иначе относительные
   `\includegraphics` и `\input` из временного каталога не находятся.
   Перед сборкой `fix_inner_tags()` переносит `\tag` из `aligned` в `align*`: внутри `aligned`
   amsmath номер запрещает, и сборка не даёт PDF (см. «Известные проблемы», п. 18).
4. **Подгонка широкого содержимого** — ступенями, пока в журнале есть `Overfull \hbox` больше 20 пт:
   таблицы: `TABLE_FIT` (поля) → `TABLE_FIT_SMALL` (шрифт) → `shrink_tabulars()`
   (обёртка каждой `tabular` в условный `\resizebox`: сжимает, только если таблица шире текста);
   затем выключные формулы: `shrink_displays()` — каждая формула измеряется и масштабируется
   до `\textwidth`, только если шире (LaTeX выключную математику сам не переносит и не сжимает),
   формулы с `\tag` сжимаются без потери номера (п. 18);
   затем строки с длинными инлайн-формулами: `soften_inline_math()` разрешает переносы после
   запятых верхнего уровня (п. 20). Всё, что сжимается через `\resizebox`, требует `graphicx` —
   его подключает `ensure_resizebox_support()`, если в тексте появился `\resizebox` (п. 19).
5. **Разбор журнала** (`parse_log`): ошибки — строки `!`; предупреждения — `Overfull` > 20 пт,
   `Missing character`, `LaTeX/Package Warning`; известный технический шум (`BENIGN_WARNINGS`:
   CJK-семейства, `Token not allowed in a PDF string`, `float specifier changed` и т.п.)
   сворачивается в одно примечание с типами: `N технических предупреждений LaTeX: <тип1>; …`
   (типы — до 3, со «…»; счётчик — все). При успешной сборке с предупреждениями журнал
   копируется рядом с PDF как `<pdf>.latex.log` (см. `log_has_issues`), чтобы разбор не
   требовал повторной сборки.
6. **Проверка результата** (`verify_pdf`): число страниц, отсутствие `\uffff`,
   наличие кириллицы, если она была в исходнике. Работает первым доступным бэкендом из
   `pdf_document_text()`: `pymupdf` → `pdfminer.six` → `pypdf`; если нет ни одного,
   проверка мягко пропускается, а в отчёте окружения так и написано.

### 4.2 Конвейер DOCX

`pandoc <исходник> -o результат.docx` — из `.md` и из `.tex` одинаково. Формулы становятся
объектами Word (OMML) и остаются редактируемыми, таблицы и стили заголовков сохраняются.
Проверка без Word (`verify_docx`): DOCX — это zip, читаем `word/document.xml` и считаем
`<w:oMath>`, `<w:tbl>`, `<w:t>`; если в исходнике есть формулы, а в DOCX их нет — предупреждение.

### 4.2а Конвейер DOCX -> Markdown (вход .docx)

Для научных документов с формулами MathType. Предполагается, что формулы уже переведены
в текст транслятором «LaTeX (Cyrillic)» (`src/make_mathtype_translator.py` его генерирует
в `res\LaTeX Cyrillic.tdl`; охват — весь блок Ѐ–џ и Ґ/ґ, четыре отсутствующие в cp1251
буквы (Ѐ Ѝ ѐ ѝ) выводятся LaTeX-акцентами вида ``\`{е}``; без этих правил MathType
при пакетной конвертации молча теряет формулы — см. «Известные проблемы», п. 15). Шаги:

1. `pandoc <docx> -t json --extract-media=<имя>.media` — дерево документа; картинки
   распаковываются в папку `<имя>.media` рядом с итоговым md (без пробелов в имени —
   LaTeX давится `\includegraphics` с пробелами).
2. `restore_docx_math` собирает формулы: инлайн `$...$` внутри текста, выключные `\[…\]`
   (многострочные размазаны по соседним абзацам — склеиваются); служебные комментарии
   `% MathType!...` выбрасываются; посимвольные `\text{н}\text{а}\text{к}\text{р}` склеиваются;
   старый `\rm{...}` заменяется; греческие команды (`\alpha` и т.п.) переводятся в юникод;
   одинокий номер формулы (без формулы) даёт предупреждение — след потери при пакетной
   конвертации. Абзацы из одной OMML-формулы (обычные Word-формулы) проходят как есть.
3. `pandoc -f json -t markdown --wrap=none` — итоговый md; юникод нормализуется NFKC
   (символы math-алфавитов U+1D4xx возвращаются к обычным буквам).

Формат **md** — отдельная галочка «Convert to»: для `.md` это копия исходника, для `.tex` —
pandoc LaTeX→Markdown, для `.docx` — восстановленный текст. Для `.md`-исходника с форматом md
копия не создаётся вовсе (файл уже в этом формате — в журнале примечание). **Исходный DOCX
никогда не перезаписывается**: нормализация docx→docx пишется отдельной копией
`<имя>.converted.docx` (формулы MathType-текста становятся объектами Word), а исходник
остаётся как был. В PDF-версии того же документа выделения маркером `[...]{.mark}` переводятся
в обычный текст: пакет soul, которым pandoc их рисует, не работает с кириллицей под xelatex
(в md они сохраняются).

**Отсутствующие картинки.** Если `.md` ссылается на картинку, которой рядом нет, конвертация
не прерывается: файл из `missing_images()` (разбор ссылок, URL и `data:` пропускаются),
перечисляется в предупреждении журнала, а в PDF-версии ссылка заменяется пометкой
«картинка не найдена: имя» (`replace_missing_images`) — иначе LaTeX на отсутствующем файле
картинки падает целиком. Для DOCX то же пропажу отмечает сам pandoc («replacing image with
description»).

### 4.3 Окно

Сверху заголовок (подзаголовок переносится по ширине) и вкладки **«Файлы»** (перетаскивание
или выбор файлов) и **«Текст»** (вставка markdown из буфера — кнопкой или Ctrl+V, правка в поле,
«Конвертировать текст»; результат сохраняется в `Документы\PDFConv` или в выбранную папку).
Ниже кнопки, галочки **Convert to: pdf / docx / md**, прогресс и **«Журнал»** — единственное место,
где видно происходящее. Верх и низ разделены сплиттером (`ttk.PanedWindow`); его положение
и размер окна запоминаются. Закрытие окна сохраняет настройки в `pdfconv.json`.
Файлы принимает вся вкладка «Файлы» (не только пунктирная зона — так промахнуться мышью
сложнее). В поле текста правый клик — «Вставить» в позицию курсора; в журнале правый клик —
«Копировать» и «Выделить всё» (журнал только для чтения, но выделять его можно).

Итог по партии — всегда три строки: сколько файлов без ошибок / с предупреждениями / с ошибками.
Статус файла: `error`, если не создан любой из отмеченных форматов или есть ошибки LaTeX;
`warnings`, если созданы оба, но есть замечания; иначе `ok`.

### 4.4 Проверки окружения (8 штук)

| Проверка | Что означает | Если `НЕТ` |
|----------|--------------|------------|
| pandoc | найден `pandoc.exe` (рядом с программой, затем `C:\Tools\pandoc`, затем PATH) | скачать `pandoc-*-windows-x86_64.zip` и положить в `bin\pandoc\` |
| MiKTeX | найдены `latexmk`/`xelatex`/`pdflatex` (Program Files, Program Files (x86), `%LOCALAPPDATA%\Programs\MiKTeX`, PATH) | поставить MiKTeX |
| Пакеты LaTeX | `kpsewhich` находит cmap, hyphenat, etoolbox, fontspec, unicode-math, geometry, xeCJK | включить автоустановку или `mpm --install=<имя>` |
| Автоустановка MiKTeX | `[MPM]AutoInstall` = 1 | MiKTeX Console → Settings → on-the-fly = Yes |
| Посторонние файлы MiKTeX | MiKTeX ничего лишнего в рабочем каталоге не создаёт | см. «Известные проблемы», п. 3 |
| Пробная сборка LaTeX | **реально собираются** тестовые документы pdflatex и xelatex, а в собранном PDF проверяется, что кириллица ищется (иначе — «PDF собрался, но кириллица в нём не ищется») | см. п. 1, 2 и 13 |
| Перетаскивание (tkinterdnd2) | библиотека подключилась | для exe не актуально; для Python-запуска `py -3 -m pip install --target lib tkinterdnd2` |
| Проверка PDF (pymupdf/pdfminer/pypdf) | проверка готового PDF доступна; в заголовке видно, каким бэкендом | необязательно; `pip install --target lib pymupdf` (или `pdfminer.six`, или `pypdf`) |

Проверки идут в отдельном потоке (пробная сборка занимает секунды), а кнопка «Проверить окружение
снова» дописывает новый отчёт в журнал — удобно после установки MiKTeX, не перезапуская окно.

## 5. Инварианты (не ломать)

- **Лицензия проекта — GPL-3.0-or-later** (`LICENSE`), сторонние компоненты и их лицензии —
  в `THIRD-PARTY.md`. PyMuPDF (AGPL-3.0) в репозиторий не добавлять; бинарник с ним
  распространяется только на условиях AGPL-3.0.

- **Вся логика конвертации — в `convert.py`.** Окно и внешняя обёртка
  (`C:\Tools\pandoc\pdfbuild.py`, если она есть) только вызывают `convert_file` / `main`.
- **Два разных корня**: `CODE_DIR` (каталог кода, `src`) и `PROJECT_DIR` (корень: папка с exe,
  иначе родитель `src`). Всё, что относится к `bin`/`lib`/`res`/`pdfconv.json`, считается от
  `PROJECT_DIR`.
- **При `sys.frozen` не подставлять `lib` в `sys.path`** — зависимости уже внутри бандла,
  лишний путь ломает импорты.
- **Сборка exe**: обязательны `--paths lib` (иначе `tkinterdnd2` и `pymupdf` не попадут в exe:
  получится 12 МБ вместо 32 и без перетаскивания) и **абсолютные пути** к иконке и скрипту
  (с `--specpath` относительные считаются от каталога `build`).
- **Сообщения для пользователя — на русском**, имена в коде — английские; комментарии только там,
  где неочевидна причина.
- **Никаких сетевых вызовов в рантайме** и никаких отправок файлов наружу.
- Версии pandoc (3.11) и PyInstaller (6.22.3) не менять без причины: от pandoc зависят `.md`
  и DOCX, от PyInstaller — воспроизводимость сборки.

## 6. Команды

```cmd
:: запуск
PDFConv.exe                                  :: без Python
pdfconv.cmd                                  :: через Python
pyw -3 src\pdfconv.pyw файл.md файл.tex      :: окно сразу с файлами

:: проверки
py -3 src\selfcheck.py                       :: всё сразу (окружение + конвертация + файлы)
py -3 src\convert.py --check                 :: только окружение, текстом
py -3 src\check_gui.py                       :: логика окна без показа (18 проверок)

:: конвертация без окна
py -3 src\convert.py файл.md файл.tex                 :: оба формата
py -3 src\convert.py --formats docx файл.md           :: только DOCX
py -3 src\convert.py --formats pdf файл.md            :: только PDF

:: пересборка
py -3 src\make_icon.py                       :: нарисовать иконку в res\PDFConv.ico
src\build-exe.cmd                            :: собрать PDFConv.exe
```

Пробный документ для ручной проверки (создать в любом каталоге):

```markdown
# Проверка

Кириллица, формула $E = mc^2$ и таблица.

| Величина | Формула |
|----------|---------|
| скорость | $v = \frac{s}{t}$ |
```

Ожидаемый результат: рядом появляются `.pdf` (1–2 страницы, текст ищется, формула нарисована)
и `.docx` (формула как объект Word, таблица). Итог: «Сконвертировано 1 из 1 без ошибок».

## 7. Известные проблемы: симптом → причина → лечение

1. **«сборка не дала PDF», в журнале — «PDF не создан, журнал пуст».** Причина: установка MiKTeX
   испорчена или обновление не завершилось (типично — обновление без прав администратора: в
   `miktex-console_admin.log` видны «Отказано в доступе» на DLL в `C:\Program Files\MiKTeX`).
   Лечение: MiKTeX Console **от имени администратора** → Updates → Update now, либо переустановка
   MiKTeX. Диагностика: `py -3 src\convert.py --check` — строка «Пробная сборка LaTeX».
2. **Проверка окружения зелёная, а сборка падает.** Причина: проверка файлов ≠ работоспособность
   (пример из п. 1: `latexmk.exe` на месте, движок не запускается). Поэтому в проверке есть
   пробная сборка; она и покажет реальную причину выводом `latexmk`.
3. **В папке программы появился каталог вида `l` с логами** (`initexmf_admin.log`,
   `miktex-console_admin.log`, `miktex-report.txt`). Это логи MiKTeX: он пишет их по
   относительному пути, потому они и оказываются рядом с текущим каталогом процесса. К работе
   приложения отношения не имеют, можно удалять. Приложение запускает свои вызовы MiKTeX
   (`kpsewhich`, `initexmf`) в отдельном временном каталоге, поэтому больше их не плодит, и есть
   отдельная проверка «MiKTeX: посторонние файлы в рабочем каталоге». Если MiKTeX умеет писать
   такую папку — в MiKTeX Console → Settings поправить путь логирования (сделать абсолютным) или
   выключить логирование в файл.
4. **Первая сборка на свежем MiKTeX падает на отсутствующем пакете.** Причина: не включена
   автоустановка (`[MPM]AutoInstall`), а спросить разрешение в неинтерактивном запуске MiKTeX не
   может. Лечение: MiKTeX Console → Settings → «Install missing packages on-the-fly: Yes»,
   либо `initexmf --set-config-value=[MPM]AutoInstall=1`, либо `mpm --install=<имя>`.
5. **Кириллица в PDF не ищется/не копируется.** Причина: pdflatex с кодировкой T2A без `cmap`.
   Конвейер добавляет `cmap` сам — **до** `fontenc` (после него `cmap` пишет «fontenc already
   loaded - some fonts may be unprocessed» и T2A-шрифты остаются без обратного соответствия;
   именно так это и ломалось: сборка зелёная, а текст в PDF извлекался как `Ïðîâåðêà`).
   Если правите преамбулу — `cmap` не удаляйте и не переносите ниже `fontenc`. С версии
   конвейера от 2026-09-22 пробная сборка сама проверяет, что кириллица в пробном PDF ищется.
6. **PDF получился формата Letter, а не A4.** Причина: pandoc без `-V geometry:a4paper`
   (в `PANDOC_ARGS` он есть).
7. **Строки или таблица вылезают за поле / обрезаны краем листа.** Причина: неразрывная
   математика, длинные идентификаторы в `\texttt`, таблица шире текста. Лечение уже встроено
   (`emergencystretch`, `[htt]`, ступени подгонки таблиц, сжатие широких выключных формул
   через `shrink_displays`); если остаётся — в отчёте будет предупреждение с первой ошибкой,
   а полный журнал сохранится рядом с исходником как `<имя>.latex.log`. Мелкие переполнения
   (до 20 пт) даются примечанием и на статус не влияют.
8. **exe собрался размером ~12 МБ и без перетаскивания.** Причина: не передан `--paths lib`.
9. **Сборка exe падает, а на месте exe остаётся файл ~300 КБ.** Причина: `--specpath` +
   относительные пути к иконке и скрипту. В `src\build-exe.cmd` пути абсолютные — не заменяйте их
   на относительные.
10. **Снимок окна получается обрезанным.** Причина: окно DPI-независимое, `PrintWindow` рендерит
    его без масштаба. Снимать надо копированием области экрана (`CopyFromScreen` с
    `SetProcessDPIAware`).
11. **DOCX не открывался в Word.** Проверка DOCX структурная (zip + XML), визуально документ
    в Word не проверялся — если есть Word, стоит открыть результат вручную.
12. **Формулы в DOCX «не формулы».** Они там как OMML-объекты Word: их видно и можно править
    в Word, но текстом они не извлекаются (поэтому `2^{19937}` не находится поиском).
13. **«Пробная сборка LaTeX» красная при живой установке MiKTeX: «PDF не создан, журнал пуст»,
    а в отчёте видна ссылка на `miktex.org/kb/fix-script-engine-not-found`** (в собственном
    журнале MiKTeX — `The script engine could not be found, scriptEngine="perl"`). Причина:
    с версии **MiKTeX 26.5** `latexmk` — это Perl-скрипт, а интерпретатор Perl **не входит**
    в дистрибутив MiKTeX и ставится отдельно (так отвечает и справка MiKTeX по этой ссылке).
    Файлы `latexmk.exe`, `pdflatex.exe`, `xelatex.exe` при этом на месте, поэтому простая
    проверка «нашёлся latexmk» зелёная, а сборка не идёт: `pdflatex`/`xelatex` напрямую
    собирают PDF, а запустить их через `latexmk` нечем. Лечение: поставить Strawberry Perl
    (<https://strawberryperl.com/>; годится portable-сборка — права администратора не нужны)
    и добавить его каталог `perl\bin` в `PATH`; проверить — `latexmk --version` (должна
    напечататься версия, а не «could not find the script engine»). Пакеты Perl конвейеру
    не нужны, только сам интерпретатор. На машине, где это встретилось, Perl поставлен
    portable-сборкой в `C:\Tools\strawberry-perl` и прописан в пользовательском `PATH`
    (реестр `HKCU\Environment`); окно и exe находят его через `PATH` процесса.
    `check_environment` теперь распознаёт этот случай и пишет готовый совет строкой
    «что сделать» вместо общей рекомендации про автоустановку пакетов, а `build_latex`
    добавляет ту же подсказку в ошибки конвертации.
    **Тень старого Perl в системном PATH.** На одной из машин в *системном* PATH остался
    ActiveState Perl 5.8.8, а пользовательский PATH в Windows приписывается *после*
    системного; обёртка `latexmk` берёт первый `perl.exe` из PATH, поэтому свежий Perl
    из пользовательского PATH она не видела даже после установки — падала с
    «File::Path version 2.08 required--this is only version 1.0901» на `latexmk.pl`
    (это тот же случай «Perl не подходит», только с другим текстом ошибки). Поэтому:
    `find_perl_dir()` в `convert.py` сначала берёт **вендорный Perl из `bin\perl`**
    (проект самодостаточен: pandoc и Perl внутри, из системного остаётся только MiKTeX),
    затем ищет подходящий интерпретатор (версия не старее 5.16) по всему PATH и в
    стандартном месте `C:\Tools\strawberry-perl\perl\bin`, а `_tool_env()` подставляет
    найденный каталог **в начало** PATH дочерних процессов — сборка идёт свежим
    Perl независимо от порядка каталогов в PATH; `script_engine_missing()` распознаёт и
    «устаревший Perl» (подпись `required--this is only version` на `latexmk.pl`), кэш
    `find_perl_dir` сбрасывается при каждой проверке окружения (кнопка «Проверить окружение
    снова» находит Perl, установленный после запуска программы).
14. **При запуске окна или exe открывается куча консольных окон, которые висят, пока идёт
    сборка.** Причина: GUI-процесс консоли не имеет, и каждый дочерний консольный процесс
    (kpsewhich, initexmf, perl, latexmk, pandoc — а их при старте и конвертации полтора
    десятка) Windows открывает в новом видимом окне; живёт оно ровно столько, сколько
    работает процесс, поэтому на больших документах окна «висят» минутами. Проявилось,
    когда заработал Perl: раньше проверки были «файловыми» и почти ничего не запускали.
    Лечение: `creationflags=NO_WINDOW` (`subprocess.CREATE_NO_WINDOW`) во всех
    `subprocess.run` в `convert.py` — флаг наследуется всей цепочкой (latexmk → perl →
    pdflatex), в CLI-режиме ничего не меняет. Проверено замером: до исправления за одну
    конвертацию плодились хосты консолей (conhost), после — ни одного нового окна.
15. **Документы MathType: пакетная конвертация молча теряет формулы.** При переводе формул
    в текст (Convert Equations → транслятор) MathType падает на первой кириллической букве
    («No translation available for 0x043D» — это «н» из Р_накр) и в пакетном режиме
    выбрасывает всю формулу, оставляя только её номер. Лечение: транслятор с кириллицей
    (`py -3 src\make_mathtype_translator.py`, файл скопировать в `Translators\`), тогда
    формулы переводятся с индексами вида `\text{накр}`. Конвертер страхует: одинокий номер
    формулы без формулы даёт предупреждение в журнале — по нему потери находят и
    допереводят вручную (в MathType: открыть формулу, Ctrl+A, Ctrl+C при настроенном
    копировании в LaTeX).
16. **Греческие буквы исчезают из PDF, собранного из md под xelatex.** Шаблон pandoc грузит
    unicode-math; команды вроде `\alpha` при основном шрифте Times New Roman уходят в
    текстовый шрифт, у которого нет математических глифов, — буква молча пропадает
    («Missing character: There is no 𝛼 in font Times New Roman»). Тот же эффект даёт старый
    `\rm{...}` из MathType. Конвейер лечит сам (`cleanup_math_code`): греческие команды
    переводятся в юникод-буквы, `\rm{...}` — в `\mathrm{...}`, одиночные буквы из-под
    `\mathrm` выпускаются; лишние Unicode-символы math-алфавитов нормализуются NFKC.
    Выделения маркером `[...]{.mark}` из PDF-версии убираются: рисующий их пакет soul
    не работает с кириллицей под xelatex (в md они сохраняются).
17. **Повторная конвертация нормализованного DOCX даёт warning «Could not convert TeX math»
    на 1–2 формулах.** Причина: в нормализованном docx формулы — OMML, pandoc пере-эмитирует
    их в свой TeX, и обратный разбор (texmath, md → OMML) спотыкается на отдельных
    конструкциях пере-эмиссии (`\right.` с хвостовым `\ `, `\mspace{6mu}`). В md и PDF формулы
    на месте; в DOCX-копии эти формулы останутся текстом TeX. Практически не встречается при
    работе от исходного MathType-документа (там конверсия чистая, предупреждений нет);
    лечится конвертацией из исходника, а не из нормализованной копии.
18. **«сборка не дала PDF — первая ошибка: Package amsmath Error: \tag not allowed here».**
    Причина: номер формулы (`\tag{...}`) стоит внутри `aligned` — так выглядит многострочная
    формула из markdown (`\[ \begin{aligned} ... \tag{6} \\ ... \end{aligned} \]`, в .tex-входе
    та же конструкция встречается в `$$...$$`), а amsmath
    разрешает `\tag` только в самой выключной формуле. Второй случай той же природы — когда
    формула с номером попадает в бокс подгонки (`\hbox`/`\resizebox`): по этой причине реальный
    документ пользователя (37 нумерованных формул, 22 страницы) не собирался вовсе.
    Лечение: `fix_inner_tags()` переносит содержимое `aligned` в `align*` (строки те же, номера
    остаются на полях), `shrink_displays()` измеряет формулу с номером-текстом, а исходный вид
    с настоящим `\tag` оставляет, если по ширине проходит. Проверено на том же документе:
    формулы (6) и (23) собираются, номера на месте.
19. **«Undefined control sequence» на `\resizebox` (и следом «Missing number, treated as zero»,
    «Illegal unit of measure»).** Причина: `\resizebox` даёт пакет `graphicx`, а шаблон pandoc
    его не подключает — ступени сжатия формул и таблиц роняли сборку там, где раньше работали
    только потому, что `graphicx` подключала сама преамбула пользователя. Лечение:
    `ensure_resizebox_support()` подключает `graphicx` в тот момент, когда в тексте появился
    `\resizebox`. Проверено: широкая таблица и широкая формула сжимаются, ошибок нет.
20. **Строка с длинной цепочкой инлайн-формул уходит за правое поле (в реальном документе —
    129 пт, то есть край листа).** Причина: LaTeX не переносит математику, а после запятой
    в формуле разрыв невозможен — в такой строке не остаётся ни одного просвета, и
    `\emergencystretch` не помогает. Лечение: `soften_inline_math()` ставит `\allowbreak`
    (нулевой штраф, ничего не печатает) после запятых верхнего уровня внутри инлайн-формул;
    запятые внутри групп и между цифрами (`3,14`) не трогаются. Ступень включается, только
    если после подгонки широкого содержимого переполнение осталось.
21. **«не удалось обновить <имя>.docx…» / «не удалось записать <имя>.pdf…».** Причина: файл
    открыт в другой программе (Word, просмотрщик) — Windows не даёт его заменить. Сообщение
    говорит, что делать: закрыть файл и повторить. Раньше в этом случае вылезала сырая
    `PermissionError` из Python.
22. **«Проверка PDF» недоступна или падает на pdfminer.** Причина: `pdfminer.six` импортирует
    `cryptography` (Rust-биндинг), а бинарные пакеты в `lib\` собраны под конкретный интерпретатор:
    проект на этой машине запускается под Python 3.15 (`py -3`), и колёса `lib` стоят под неё
    (charset-normalizer/cffi — cp315, cryptography — cp315-abi3). Запуск тем же кодом под 3.14
    даёт «ImportError: DLL load failed while importing _rust» на pdfminer — лестница
    `pdf_document_text()` мягко откатывается на следующий бэкенд (`pymupdf` → `pdfminer` →
    `pypdf`). Лечение: переустановить `lib` тем же Python:
    `py -3 -m pip install --target lib pdfminer.six pypdf`. Проверено на 3.15: все три бэкенда
    извлекают кириллицу и искомое слово из PDF конвейера, отчёт окружения показывает активный
    бэкенд, а при отсутствии всех — честную строку «не установлена» вместо падения.

## 8. Как проверялось (что уже доказано)

- `selfcheck.py` и `convert.py --check`: восемь проверок окружения, пробная конвертация,
  круг docx -> md с формулой.
- Реальный документ пользователя (16 страниц, ~250 инлайн- и 21 выключная формула): PDF 17 страниц
  с живым текстовым слоем; DOCX — 312 формул Word, 1 таблица, 25 стилей заголовков; одинаково
  из `.md` и из `.tex`; в пути с пробелами и кириллицей тоже.
- Реальный документ MathType (фрагмент диссертации, 7 формул с русскими индексами вида
  Р_накр, многострочные системы, таблица с графиками): после Convert Equations (LaTeX
  Cyrillic) — md со всеми формулами, PDF 3 страницы без потерянных глифов, DOCX с формулами
  Word; двумя дорогами (прототип и конвейер конвертера) результат идентичен.
- Широкая таблица (на 2.5 см шире текста) поджимается автоматически, все колонки видны.
- `check_gui.py` — 18 проверок: вкладки, вставка из буфера (в том числе «в буфере нет текста»),
  имя файла из заголовка, защита от пустого текста и от снятых форматов, проверка окружения
  в журнале, отсутствие удалённой панели.
- exe: самостоятельность проверена запуском из пустой папки (только exe и `bin\pandoc`):
  конвертируются оба формата, в журнале всё зелёное; без `bin\pandoc` рядом находит pandoc
  в `C:\Tools\pandoc`.
- Окно проверено снимками экрана (вкладки, сплиттер, перенос подзаголовка, журнал).
